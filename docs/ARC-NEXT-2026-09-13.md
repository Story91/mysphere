Startpad and PERPS already run on Arc Testnet. Do not rebuild them. Startpad's active Arc configuration uses R_VIRT=250 (graduation at 1,000 USDC). Mainnet deployment tooling already exists and defaults to R_VIRT=1250 (5,000 USDC); this is a separate immutable deployment, not a migration of test tokens or positions.

The UI review found 8 active curves and 123 indexed trades on Arc, and three PERPS markets. These are testnet activity, not evidence of organic acquisition. No transactions were submitted in this review.

## Read-only deployment check

Run `node scripts/arc-preflight.mjs` for the existing testnet manifest. For another deployment pass its JSON path and set `ARC_PREFLIGHT_RPC_URL` to a verified provider. The script checks actual chain ID, head freshness, deployed bytecode, ERC-20 decimals, factory wiring, insurance funding and governance contract code. It never loads wallet keys or sends transactions. Exit 1 means a check failed or could not be completed. A contract governance address still needs manual review of threshold, owners and delay.

Live validation at Arc Testnet block 61,963,879: 11 checks passed, governance contract-code check failed. The configured governance address has no contract code. Insurance accounting balance was 1.857865 testnet USDC and current required balance was zero. Exit 1 is the intended result, not a successful production-readiness verdict.

## Remaining launch gates

1. Confirm official public-mainnet RPC, explorer, chain ID and dependency addresses. Existing repo discovery through a third-party RPC is not official confirmation. Keep testnet accessible as a separate network.
2. Review PythReceiver ownership: owner can replace guardian keys. Production requires reviewed governance (multisig and delay) or an official receiver. Existing addresses and keys are not automatically a production configuration.
3. Harden and independently review oracle policy before redeployment: confidence interval, future timestamps, per-asset age limits, market hours, handling feed reverts, and explicit policy on registry fallback. Current adapter ignores confidence and uses a one-hour age limit; changing local source does not change immutable deployed markets.
4. Rehearse deploy, launch, buy, sell, graduate, pool swap and fee claim; PERPS open, funding, close and liquidation. Choose risk/capital parameters from stress tests. A 1% insurance floor is not proof of solvency.
5. Deploy the keeper on durable infrastructure with funded gas, verified feed entitlements and alerts for price age, missed liquidation, failed updates and fund coverage. A keeper script in the repo is not an uptime guarantee.
6. Record transaction hashes, block numbers, constructor parameters and verified source for each mainnet deployment. Do not claim mainnet availability in posts until confirmed.

## ARC capabilities that fit MySphere

### First: crosschain USDC onboarding

The current wallet links to Base Bridge; the repository has CCTP round-trip scripts, not a complete in-app funding flow. Circle App Kit / Unified Balance fits users arriving from Base to use Startpad or PERPS on Arc. Start with a separately tested flow: choose source and amount, quote full fees, approve, track attestation/claim, recover after reload, and show destination spendable USDC including gas. Check the supported-chain list at integration time. Smart contract wallets can require a delegate workflow: never assume all existing Base accounts can sign a Gateway spend directly.

### Second: paid work using existing Asks

ERC-8183 on Arc defines funded jobs with provider, evaluator, deliverable and settlement. Evaluate an adapter for existing Asks rather than a separate marketplace. Current Ask escrow semantics must be mapped explicitly: provider sets the budget in the reference contract, and evaluator decides completion/rejection. Preserve existing Base Asks and test expiry/refund/dispute behavior before enabling real money.

### Third: agent identity

ERC-8004 could replace unsupported identity claims with verifiable registration and reputation. Local KYA is a registry wrapper, so first distinguish local profile from onchain registration in the UI. Onchain identity is not certification of an agent's safety or quality.

Do not add USYC yield as a general retail retention feature: ARC's current documentation lists institutional eligibility restrictions. Do not add more markets solely to increase the visible count.

## Retention experiment using existing features

Invite independent creators to scheduled launches; promote their existing share cards/feed posts and creator revenue. For PERPS, invite testers to complete open/funding/close and return a week later. Track independent funded users, successful first actions, 7-day return and failure rate; exclude seed wallets and test automation from acquisition figures. Do not promise ARC airdrops or rewards without a funded, published policy.
